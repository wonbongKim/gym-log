# gym-log

개인 운동 루틴을 정의하고 운동을 기록하는 **모바일 우선 웹앱**.
혼자 쓰는 메모용 도구로, 서버 없이 브라우저 LocalStorage에만 데이터를 저장한다.

---

## 핵심 원칙

- **개인용 / 단일 사용자** — 로그인·인증·동기화 없음
- **서버리스** — 모든 데이터는 브라우저 LocalStorage에 저장
- **모바일 우선** — 운동 중 한 손으로 빠르게 입력
- **기록은 사실(fact)** — 루틴(템플릿)을 수정·삭제해도 과거 기록은 보존
- **백업은 사용자 책임** — JSON 내보내기/가져오기로 직접 백업

---

## 기술 스택

```
React + Vite (react-ts 템플릿)
TypeScript
CSS Modules + CSS 변수 (디자인 토큰)
LocalStorage (데이터 저장)
GitHub Pages (배포)
```

- **TypeScript**: 루틴/종목/기록/세션 스키마를 `type`으로 정의해 데이터 구조를 강제.
  특히 LocalStorage `JSON.parse` 결과는 타입 가드로 검증한다.
- **CSS Modules + CSS 변수**: Tailwind 없이 컴포넌트별 스코프 + 디자인 토큰(색상/간격/둥근
  모서리/터치 타깃 크기)으로 모던 UI를 구성. 작은 앱 규모에 맞춘 선택.

## 데이터 구조

### LocalStorage 키

| 키 | 내용 |
|---|---|
| `gymlog_exercises` | 직접 추가한 종목 (기본 종목은 앱에 내장) |
| `gymlog_routines` | 루틴 정의 |
| `gymlog_logs` | 운동 기록 |
| `gymlog_session` | 진행 중인 운동 세션 (임시) |
| `gymlog_settings` | 앱 설정 (휴식 시간·알림음·화면 켜짐·마지막 백업 시각) |

각 키의 값은 최상위에 `version` 필드를 두어 향후 스키마 마이그레이션에 대비한다.

### 1) 운동 종목 = 기본 종목(JSON) + 내 종목(`gymlog_exercises`)

루틴과 기록은 종목을 `id`로 참조한다. 이름이 조금 달라도(띄어쓰기·별칭) 같은 종목이면 같은 id로 묶여
"벤치프레스 무게 추이" 같은 종목별 기록이 쪼개지지 않는다.

- **기본 종목**: [`src/data/exercises.json`](src/data/exercises.json) — 앱에 내장, id 고정(예: `bench_press`).
  고치려면 이 파일을 수정하고 배포한다.
- **내 종목**: 목록에 없는 이름을 입력하면 `gymlog_exercises`에 새로 만들어진다(id `ex_…`).
- 이름 비교는 공백·대소문자·구두점을 무시한다(`벤치 프레스` = `벤치프레스`).
  `aliases`의 다른 이름도 같은 종목으로 인식한다(`사레레` → 사이드 레터럴 레이즈).
- 앱을 열 때·백업을 복원할 때, 기본 종목과 이름이 같은 내 종목은 **기본 종목으로 자동으로 합친다**
  (기록·루틴·진행 중 운동의 id를 옮김, 기록 당시 이름은 그대로).

```jsonc
// src/data/exercises.json — 종목 하나
{
  "id": "bench_press",                  // 영문 소문자·숫자·_ — 한 번 정하면 바꾸거나 지우지 않기(기록이 이 id를 가리킴)
  "name": "벤치프레스",                  // 화면에 보이는 이름
  "aliases": ["바벨 벤치프레스", "벤치"], // (선택) 같은 종목으로 인식할 다른 이름
  "muscle": "chest",                    // chest | back | shoulders | legs | arms | core — 선택 화면 분류
  "pattern": "chest_press",             // 동작 패턴 — 같은 패턴끼리 대체 종목으로 추천 (목록은 src/types.ts)
  "equipment": "barbell"                // (선택) barbell | dumbbell | machine | cable | smith | bodyweight | assisted
}
```

> 이름·별칭이 다른 종목과 겹치거나 값이 잘못되면 개발 서버 콘솔에 `[exercises.json] 확인이 필요해요`로 알려 준다.
> 0kg을 "빈봉"으로 표시하는 건 바벨·스미스(또는 기구 정보가 없는 종목)뿐이다.

### 2) 루틴 정의 (`gymlog_routines`)

루틴은 **템플릿**이다. 종목은 마스터를 `exerciseId`로 참조한다.

```jsonc
{
  "version": 1,
  "routines": [
    {
      "id": "rt_uuid",
      "name": "월요일 - 가슴/등/삼두",
      "days": ["mon"],            // 월~일 멀티 선택
      "exercises": [
        {
          "exerciseId": "ex_uuid",  // 마스터 참조
          "targetSets": 3,
          "targetReps": "8~10",
          "order": 0                // 종목 순서
        }
      ]
    }
  ]
}
```

### 3) 운동 기록 (`gymlog_logs`)

기록은 **사실**이다. 루틴/종목이 나중에 바뀌거나 삭제돼도 기록은 그대로 남아야 하므로,
기록 시점의 **이름을 snapshot으로 함께 저장**한다(`routineName`, `exerciseName`).

```jsonc
{
  "version": 1,
  "logs": [
    {
      "id": "log_uuid",
      "date": "2026-06-26",
      "routineId": "rt_uuid",
      "routineName": "월요일 - 가슴/등/삼두",   // snapshot
      "startedAt": "2026-06-26T09:00:00+09:00",
      "finishedAt": "2026-06-26T10:05:00+09:00",
      "exercises": [
        {
          "exerciseId": "ex_uuid",
          "exerciseName": "벤치프레스",          // snapshot
          "sets": [
            { "setNo": 1, "kg": 80, "reps": 10 },
            { "setNo": 2, "kg": 80, "reps": 8 },
            { "setNo": 3, "kg": 75, "reps": 8 }
          ]
        }
      ]
    }
  ]
}
```

- `kg`는 `number | null` — 맨몸 운동은 `null`, 어시스트 머신은 음수 허용
- `routineId` / `exerciseId`는 참조 편의를 위해 유지하되, 표시는 항상 snapshot 이름 사용

### 4) 진행 중 세션 (`gymlog_session`)

운동 중 앱을 나갔다가 돌아와도 **이어서 기록**할 수 있도록, 세트를 입력할 때마다 즉시 저장한다.
"운동 종료" 시 이 세션을 `gymlog_logs`로 확정하고 세션을 비운다.

```jsonc
{
  "version": 1,
  "session": {
    "routineId": "rt_uuid",
    "routineName": "월요일 - 가슴/등/삼두",
    "startedAt": "2026-06-26T09:00:00+09:00",
    "exercises": [ /* logs.exercises와 동일 형태, 작성 중 상태 */ ]
  }
}
```

## 화면 구성

### 0. 네비게이션

- 하단 탭바: **홈 · 기록 · 루틴** (화면 4개 규모에 맞춘 단순 구조)
- 운동 실행은 탭이 아니라 **풀스크린 모드**로 진입 (집중 흐름)

### 1. 홈 (대시보드)

"운동해라"고 강요하는 단일 동선이 아니라, **오늘을 보여주고 동기를 주며 어디든 갈 수 있는**
대시보드형 홈. 위에서 아래로 우선순위 순 배치.

```
┌─────────────────────────────┐
│  6월 26일 금요일             │   날짜 + 가벼운 인사
│  이번 주 3회 운동 🔥         │   주간 요약(동기 부여)
├─────────────────────────────┤
│  ▶ 운동 이어하기            │   진행 중 세션 있을 때만 (최상단)
│     상체 B · 2/7 종목        │
├─────────────────────────────┤
│  오늘의 루틴                │
│  ┌───────────────────────┐  │
│  │ 금요일 - 어깨/등/이두 │  │
│  │ 7개 종목 · 예상 60분  │  │
│  │        [ 운동 시작 ]  │  │   주 액션 버튼
│  └───────────────────────┘  │
├─────────────────────────────┤
│  최근 기록                  │
│  · 6/24 하체 (5종목)        │   탭하면 상세로
│  · 6/22 상체 A (7종목)      │
├─────────────────────────────┤
│  [루틴 관리]   [기록 전체]  │   보조 진입점
└─────────────────────────────┘
```

구성 요소(우선순위 순):

1. **운동 이어하기** — 진행 중 세션(`gymlog_session`)이 있을 때만 최상단 노출.
   없으면 카드 숨김. 운동 중 이탈 후 복귀 동선이 가장 중요
2. **주간 요약** — "이번 주 N회" 같은 가벼운 통계로 재방문 동기 부여
3. **오늘의 루틴 카드** — 바로 점프가 아니라 종목 수·예상 시간을 먼저 보여주고
   카드 안의 명확한 **[운동 시작]** 버튼으로 진입
4. **휴식일 대응** — 오늘 루틴이 없으면 "오늘은 휴식일 💤" + "그래도 운동하기
   (다른 루틴 선택)" 버튼
5. **최근 기록 미리보기** — 히스토리 탭에 들어가지 않아도 홈에서 최근 흐름 확인
6. **보조 진입점** — 루틴 관리 / 기록 전체로 언제든 이동

### 2. 루틴 관리

- 루틴 목록 / 추가 / 수정 / 삭제
  - 루틴 이름, 요일 멀티 선택(월~일)
  - 종목 추가: 이름 입력(기본 종목 자동완성, 별칭이면 "→ 벤치프레스(으)로 저장돼요",
    처음 보는 이름이면 내 종목으로 추가) + 목표 세트/횟수
  - 종목 순서 변경(드래그 또는 ▲▼)
- 루틴 삭제 시 **과거 기록은 보존**됨을 명시
- 종목별 **대체 종목·메모**(수행 팁) 설정 — 운동 중 "대체" 시 대체 종목을 먼저 추천
- **JSON·AI로 루틴 가져오기** (`#/routines/import`) — API 연동 없이 복사/붙여넣기만:
  1. "AI 요청문 복사" → 형식 설명 + 현재 루틴 JSON + **종목 이름 목록**(부위별) + 원하는 변경사항 자리가 담긴 문구를 AI 채팅에 붙여넣기
  2. AI 답변을 통째로 붙여넣기 (코드 블록 안 JSON만 읽음) → 미리보기에서 새 루틴/수정/변경 없음 + 바뀐 점 확인.
     별칭으로 연결된 종목은 "→ 정식 이름", 목록에 없는 이름은 **처음 보는 종목**으로 표시(지난 기록과 안 이어짐)
  3. 적용 방식: **새로 추가** / **같으면 수정**(id → 이름 순으로 매칭, 기존 id 유지 → 지난 기록 연결 유지) /
     **전체 바꾸기**(붙여넣은 목록이 전체, 빠진 루틴 삭제 — 확인 후 적용), 모두 **되돌리기** 지원

### 3. 운동 실행

- 종목별 세트 기록 (kg / reps)
- **직전 기록 표시**: 같은 종목의 가장 최근 기록을 "지난번 80kg×10"으로 보여주고,
  입력칸 **기본값으로 자동 채움** → 운동 중 입력 마찰 최소화
- 세트 추가 / 삭제 / **세트별 완료 체크** (종목의 모든 세트를 끝내면 카드가 접히고 다음 종목으로 스크롤)
- **휴식 타이머**: 세트를 체크하면 자동 시작, ±15초·건너뛰기, 종료 시 진동/알림음 (기본 시간은 설정)
- 경과 시간·진행률 바, 운동 중 **화면 꺼짐 방지**(Wake Lock 지원 기기)
- 운동 중 종목 추가 / 이번 운동에서 빼기 (루틴은 그대로) — 종목 선택은 이름·별칭 검색, 부위별 보기, 자주 한 종목 먼저
- **기구가 사용 중일 때**: 카드의 ⇄ 버튼으로 **다른 종목으로 대체**(루틴에 지정한 대체 종목 → 전에 대신했던 종목 →
  **같은 동작 패턴의 다른 기구** 순으로 추천,
  이미 끝낸 세트는 원래 종목으로 남김, 기록에 "○○ 대신" 표시) 또는 **나중에 하기(맨 뒤로)**
- **메모**: 세트 번호를 누르면 세트 메모(가동범위 부족·통증 등 빠른 태그 + 자유 입력), ⋯ 메뉴에서 종목 메모.
  다음 운동 때 "지난번 메모"로 다시 보여줌
- **오늘의 목표**(더블 프로그레션): 지난번 모든 세트가 목표 횟수 상단에 닿았으면 "무게 올릴 차례", 아니면 "같은 무게로 +1회"
- 세트 입력 시마다 `gymlog_session`에 즉시 저장
- "운동 완료" → 미완료 세트가 있으면 "완료한 세트만 / 입력한 세트 모두" 중 선택해 기록 확정(`gymlog_logs`),
  횟수가 빈 세트는 제외 → 기록 요약 화면(신기록 표시)으로 이동

### 4. 기록 히스토리

- **월간 달력** + 월 합계(횟수·세트·볼륨), 날짜별 기록 목록 / 상세 보기
- **종목별 성장**: 추정 1RM(Epley)·최고 무게·볼륨 추이 그래프 + 전체 기록 표
- **개인 신기록(PR)** 자동 감지 — 이전 기록 대비 최고 무게/추정 1RM/최다 횟수
- **점진적 과부하 판정** — 같은 종목의 직전 수행과 비교해 ↑/=/↓ 와 이유("무게 +2.5kg", "80kg에서 +3회", "볼륨 +120kg")를
  운동 중(종목 완료 시)·기록 상세·종목별 성장(성공률)에 표시
  - 비교 기준: **같은 루틴의 직전 수행** 우선. 없으면 같은 종목을 따로 하는 다른 현재 루틴(예: 월/금 강도 차이)은 건너뛰고 그 외 가장 최근 수행 (운동 시작 시 기본값 채움도 같은 기준) · 판정: 최고 무게 ↑ → 무게를 내렸으면 추정 1RM이 오를 때만 ↑ → 같은 무게면 세트 단위 횟수 비교(세트 수만 적은 건 "유지") · 종목별 성장 화면에서 루틴별로 나눠 보기
- **기간별 내보내기 (AI 분석용)** — 1·3·6개월/전체, 세트를 `"80x10"`으로 압축한 요약 JSON + 종목별 추이 +
  직전 대비 판정 + 메모, "분석 요청 문구" 포함 옵션. 복사·공유·파일 저장만 하며 **외부 API 호출 없음**
- **JSON 내보내기 / 가져오기** (수동 백업/복원, 마지막 백업 시점 표시)

### 무게 입력 규칙

| 입력 | 의미 |
|---|---|
| 숫자 | kg, 바벨 종목은 **빈봉을 뺀 원판 무게** |
| `0` | **빈봉**만 (화면에 "빈봉" 표시) |
| 빈칸 | 맨몸 |
| 음수 | 어시스트 머신의 보조 무게 (0에 가까울수록 어려움) |

### 공통 UX

- 상세/편집 화면은 URL 라우트(`#/routines/:id`, `#/history/log/:id` 등)라 **브라우저 뒤로가기로 닫힘**
- 브라우저 기본 `confirm/alert` 대신 하단 시트 다이얼로그 + 토스트, 삭제는 **되돌리기** 지원
- **PWA**: 홈 화면에 설치, 오프라인 실행(서비스 워커는 프로덕션 빌드에서만 등록)

## 데이터 보관 정책

- **자동 삭제 없음** — 기본적으로 모든 기록을 보존한다.
- **용량 한계 시에만 정리** — LocalStorage 쓰기가 quota 초과(`QuotaExceededError`)로
  실패할 때에 한해, 사용자에게 알리고 **오래된 기록부터** 정리하는 옵션을 제공한다.
  (예상 용량은 3개월 ~270KB 수준이라 평상시엔 발생하지 않음)
  - 운동 저장 시 가득 찼으면: 가장 오래된 기록부터 **필요한 만큼만**(2%씩) 지우며 재시도 후 저장
  - 운동 중 입력이 저장 안 되면: 가장 오래된 기록 10%를 정리할지 묻는다 (30초 내 중복 안내 없음)
- 정리 전 **JSON 내보내기(백업)를 먼저 유도**한다.
- 기록 탭 → 내보내기 시트에서 **저장 공간 사용량**과 수동 정리(1년/6개월 이전, 가장 오래된 10개) 제공
- `navigator.storage.persist()`로 브라우저의 임의 삭제를 막도록 요청한다.
- 참고: GitHub Pages(`<아이디>.github.io`)는 같은 아이디의 다른 저장소 사이트와 LocalStorage 한도를 공유한다.
  iOS Safari는 홈 화면에 추가하지 않은 사이트의 데이터를 장기간 미사용 시 지울 수 있으니 **홈 화면 설치**를 권장.
